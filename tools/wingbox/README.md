# tools/wingbox — розкладка крил «по дузі» (3D)

Інструменти, якими проєктуємо обидва крила кімнати в справжньому 3D у перспективі кімнати. Розкладка (`js/objects/arc_layout.js`,
`NX.arcLayout`) — дані для піксельного 3D (`js/objects/arc_scene.js`, рушій `js/core/px3d.js`; див. docs/HANDOFF.md).
**Чиста основа (29.10)** — зони додаються по черзі (параметр `n` у крила, див. нижче). **Крок 1:** перші зони — майстерня
(`workshop()`: з оригінальної картинки, масивна, ближча — `far.front`) і маркетинг (`marketing()`: будка візуально по центру стола).

## Файли

| Файл | Що робить |
|---|---|
| `gen_room.py` | генератор: стіни-дуги + зони з частин картинки `assets/room.webp` у 3D; перевірки; план зверху; `--write` пише в `js/objects/arc_layout.js` |
| `plan.py` | геометрія: проєкція кімнати `P3`, грані `faces`, слід `footprint`, роздільна лінія `sep`, крива `catmull` |
| `shot.js` | знімки з `dist/nexora-lab.html` (коли 3D зібралось): комп'ютер, кімната, ліве / праве крило, телефон 390×844, список об'єктів |
| `layout.json` | остання розкладка (те саме, що вшито в `arc_layout.js`) |

## Як користуватись

```bash
python3 tools/wingbox/gen_room.py --plan /tmp/plan.png --write   # розкладка + план + записати в js/objects/arc_layout.js
python3 tools/build.py                                          # зібрати dist/
node tools/wingbox/shot.js /tmp/s desk roomc zoomL zoomR ph     # знімки (/tmp/s_desk.png …)
node tools/wingbox/shot.js /tmp/p desk --hash lang-pl           # те саме іншою мовою
node tools/wingbox/shot.js /tmp/x roomc --layout my.json         # спробувати іншу розкладку без --write і без збірки
node tools/wingbox/shot.js /tmp/c desk ph --clean 1             # без бабла Nexi (PHX='[["ph1",385],["ph2",900]]' — телефон на зонах)
python3 tools/wingbox/gen_room.py /tmp/v1.json --preset v1 --plan /tmp/v1.png   # попередня спроба (28.10: 6 однакових зон)
python3 tools/wingbox/gen_room.py /tmp/a3.json --preset all3    # нинішні параметри з усіма трьома зонами: чи вмістяться наступні
```

Генератор друкує для кожного крила масштаби, висоти зон на екрані, проміжок кожної зони до стіни (`wall gap`), проміжки між
зонами на екрані (`SEP`: головні частини / усе — мають бути > 0, щоб зони не зливались), `INTERSECT` (перетини об'ємів) і
`BEHIND WALL` (що стоїть за стіною) — обидва мають бути `none`; і які колони не влізли між зонами (тоді їх немає).

## Геометрія

- Перспектива як у кімнаті (`js/core/persp.js`): точка сходу VP (774, 220), D 520, око (774, 220, −520); світ — x вправо,
  y вниз (підлога 372), z углиб (0 — площина картинки).
- Вікно — `NX.cfg.WIN` у `js/core/config.js` (зараз 508..1040, центр 774). Генератор читає його звідти; відкоси стоять
  на глибині z 185. Диван на плані — там, де він у кімнаті (`NX.cfg.SOFA_Y`).
- Кімната зверху — пів кола: від відкосу коротка пряма стіна до `xf` (1200), далі дуга (центр C = (xf, 185 − R), R 225) до
  глядача. Ліва стіна — дзеркало правої відносно x 774. План — `--plan`.

## Параметри (`DEFAULT` унизу `gen_room.py` або `--params файл.json`)

- `R`, `xf` — радіус дуги й де починається дуга.
- `H` — висоти головних частин зон на екрані (px) по позиціях `[дальня, середня, найближча]` (або одне число для всіх); масштаб
  кожної зони підбирається під свою висоту (`fit_far` / `fit_chain`). Зараз `[240, 180, 135]` (власник: перші — найбільші, далі
  на ~25 % менші). Головні частини зони — третій аргумент `Zone(...)`; генератор пише їх у розкладку (`mains`).
- У крила (`right` / `left`):
  - `n` — скільки зон ланцюжка будувати (0..3): праворуч майстерня → інструменти → портал, ліворуч маркетинг → аналітика →
    AI-центр (від вікна до глядача). Зараз `n` 1 — перші зони. `zones` — імена заготовок (`BUILDERS`; за замовчуванням нові).
  - `far.X_in` — край дальньої зони біля дивану (екранний x — найближча до середини точка зони; бісекцією), `far.gap` —
    найменший проміжок до стіни з вікном, `far.front` — лінія підлоги під передом зони на екрані (зона ближче до глядача, але
    спина — не далі за стіну);
  - `gz` / `gs` — проміжок до попередньої зони (у плані, од. світу / на екрані, px), `gw` — до стіни.
  - за потреби: `hub` — екран на стіні біля вікна, `mz` — антресоль (з ботами, вазонами, підвісами), `cols` — колони між
    зонами (лише якщо влазять), `shelves` — настінні полиці з речами, `hang` — підвіси (ліани, лампи). Приклади — `PRESETS['v1']`.
- Зони — ЛАНЦЮЖКОМ уздовж стіни: дальня (біля вікна) — прямо, спиною до стіни з вікном (`far_items`); середня й найближча —
  спиною до дуги й лицем до її центру, кожна впритул до попередньої (`chain`: найменший кут на дузі, за якого до попередньої
  зони `gz` од. у плані й `gs` px на екрані). Нічого не заходить одне на одне.
- Кожна зона — частини картинки: `Z.add(id, X0, X1, Y0, Y1, v, d, стиль, …)` — прямокутник частини на картинці, відступ углиб
  `v` і глибина `d` (у пікселях картинки). `on='id'` — стоїть на іншій частині; `cyl` — циліндр; `deco` — оздоби на лицьовій
  грані (частки грані); `ch` — зрізані кути; `kt`/`kb` — зрізаний конус (купол); `sty` — товщі фаска / шов / неоновий кант
  великих частин (px картинки) і колір канта `neon`. `mirror(Z, id, …)` — частина й дзеркальна пара (`idL`/`idR`).
  `Z.arm` / `Z.armv` — маніпулятор (точки в px картинки, глибина) -> розкладка `arm` + `armk` (товщина під масштаб зони).
  **`Z.vc` — візуально по центру** (`vcenter`): група частин за столом (будка з вивіскою, пара моніторів) зсувається так, щоб
  на екрані її середина припала на середину лиця стола — бо в перспективі дальнє «з'їжджає» до точки сходу.
  Нові зони — `workshop()`, `marketing()`; заготовки 28.10 — `workshop_v1()`, `tools()`, `portal()`, `marketing_v1()`,
  `analytics()`, `aicenter()`.
