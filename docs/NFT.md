## Що вирішив власник (02.11)
Слова власника: «тепер у кожного користувача може бути персональний скін — повторювати скіни не можна; можна зробити так, щоб
щось одне не співпадало — тоді пройде; кожен такий скін — 99,99 € і автоматично NFT, один екземпляр; у майстерні можна десь
побачити всіх власників Nexi з їхніми Nexi; мати можна лише один». Уточнення (02.11, пізніше): «будь-який Nexi, щоб придбати
собі, — 99,99 €; кожен має свій номер, починаючи від одного — Nexi #1 я забираю собі, наступний — #2 і так далі; під кожен
скін — своя картка NFT: скін + номер; повністю 1 в 1 скін не повторюється — має бути хоч якась відмінність».

| Питання | Рішення |
|---|---|
| Персональний Nexi | будь-яке поєднання 8 частин — своє **або готовий скін як є**; двоє не можуть мати однакового — досить, щоб відрізнялась **хоча б одна** частина |
| Номери | **за чергою покупок, з #001**: #001 — засновник (власник проєкту), перший покупець — #002, далі #003…; картка NFT = скін + номер (у аркуші купівлі — номер, який отримає покупець) |
| Ціна | **99,99 €** за кожен (для покупців з ЄС ціна вказується з ПДВ) |
| NFT | кожен персональний Nexi — **NFT 1/1** (один екземпляр) |
| Оплата й гаманець | **картка / iDEAL / Apple Pay; гаманець для NFT створюється сам за email** (без знань крипти; NFT можна вивести в свій гаманець) |
| Мережа | **Base** (Coinbase, поверх Ethereum): випуск — копійки, видно на OpenSea |
| Перепродаж | **можна** (OpenSea тощо), Nexora — роялті з перепродажів (розмір вирішити; маркетплейси не зобов'язані платити); новий власник NFT = новий власник Nexi в Nexora |
| Один на людину | у застосунку — один персональний Nexi на акаунт; у контракті — не більше одного Nexi на гаманець |
| Безкоштовно | **стандартний Nexi («Класика») — у всіх, не продається**; 16 інших готових скінів — безкоштовно, **поки їх не купили**: готовий скін теж продається як є, один раз — тоді він лише в покупця (іншим — приміряти; хто носив, повертається до стандарту — Nexi про це скаже); у лабораторії **приміряти можна будь-що**, а залишити своє поєднання — лише купивши |
| Де видно власників | лабораторія скінів — вкладка **ВЛАСНИКИ** (картка NFT кожного); голограма зони СКІНИ (до 02.11 — «Майстерня») — кожен третій показ — Nexi власника з ім'ям і номером |

## Правила в коді (`js/actors/nexi/owners.js`)
- **ДНК образу — 8 частин:** колір (`theme`), тулуб, руки, ноги, антена, голова, спина, реліквія (`hand`). Обличчя — емоції
  Nexi, ефекти — його настрій (`nexi.js`), тож у скін не входять.
- **Ключ** `theme/body/arms/legs/ant/head/back/hand` (`-` — нічого), напр. `neon/circuit/neon/sneakers/halo/phones/wings/blade`
  — за ним унікальність у базі (UNIQUE) і в контракті (`keccak256(key)`), він же — атрибути NFT. Ключ спирається на id частин,
  тож нові скіни в каталозі (`skins.js`) старих ключів не ламають (id частин не перейменовувати!).
- **Код** `NX-XXXXXX` — коротке ім'я для людей (хеш ключа, Crockford base32) — на картці NFT і в лабораторії.
- **Стандартний образ** («Класика», `STD`) — у всіх, не продається й не може мати власника. **Готові скіни** (16, без реліквії) —
  безкоштовні, поки їх не купили; купити — як є, один раз (`ownerOf(id)` — хто купив).
- Можливих поєднань: 25 × 16 × 8 × 8 × 11 × 10 × 5 × 13 = **183 040 000** (мінус стандартний — продається решта).
- Стан образу: `std` (стандарт) · `preset` (готовий, ще не куплений: носити — безкоштовно, купити — можна) · `avail` (своє
  поєднання — купити) · `taken` (має власник — «зміни хоча б одну річ»; і готовий скін теж) · `mine`. `forSale(look)`.
- **Номер** наступного покупця — `nextNo()`: після засновника (`FOUNDER` = 1) і всіх куплених; на кроці 2 номер дає сервер
  під час оплати (за чергою оплат).
- Збережене в браузері (`localStorage nexi-look`) — лише те, що можна залишити; старий збережений «власний» образ при запуску
  стає стандартним або готовим скіном (`sanitize`). **Вибір зберігається сам** (02.11, власник: «скін, який людина обрала,
  має зберігатися — коли заходить повторно, у кожного лишається такий, який був»): кожна зміна, яку можна залишити, одразу
  пишеться (`skinlab.js: persist`), кнопка показує «ЗБЕРЕЖЕНО»; поки акаунтів немає — у кожного браузера свій.

## Як працюватиме покупка (кроки 2–4)
```
Лабораторія -> «КУПИТИ · 99,99 €» -> вхід за email (код на пошту) — тим самим email створюється гаманець на Base
  -> бекенд перевіряє ключ і РЕЗЕРВУЄ його на 15 хв (щоб двоє не купили той самий одночасно)
  -> оплата (Checkout: картка / iDEAL / Apple Pay / Google Pay, EUR, з ПДВ; галочка «погоджуюсь на негайне виконання»)
  -> webhook «оплачено» -> власник у базі (номер — наступний) -> мінт NFT на гаманець покупця (газ — наш, на Base дрібниці)
  -> у застосунку: «Твій Nexi #00N», скін збережено в акаунті; у ВЛАСНИКАХ і на голограмі — новий власник
Перепродаж (OpenSea): подія Transfer у контракті -> бекенд міняє власника; новий власник входить своїм гаманцем (SIWE).
Невдала оплата / минув резерв -> ключ знову вільний.
```

### Бекенд і акаунти (крок 2)
- **Vercel Functions** (папка `api/`) або Cloudflare Workers + **Postgres** (Neon / Supabase).
- Таблиці: `owners` (no — номер, key UNIQUE, code, wallet UNIQUE, email, name ≤ 18 знаків, status reserved/paid/minted,
  token_id, tx, created_at), `holds` (key UNIQUE, expires_at, user), `events` (журнал webhook-ів і Transfer).
- API: `GET /api/owners` (список для лабораторії й голограми — `NX.owners.api = '/api'`), `GET /api/status?key=`,
  `POST /api/checkout` (потрібен вхід: резерв + посилання на оплату), `POST /api/webhook` (оплата), `GET /api/me`,
  `GET /api/nft/:id` (метадані, якщо не IPFS).
- **Вхід за email і гаманець:** Coinbase Developer Platform — Embedded Wallets (вхід email / SMS / соцмережі, без seed-фрази,
  користувач може експортувати ключі; Base підтримується; там же серверний гаманець для мінту) — або Privy (тепер належить
  Stripe). Обрати на кроці 2.
- Засновник (власник проєкту) — запис **#001 «Засновник»** (див. нижче).
- **Однаково для всіх** (власник, 02.11: «якщо два перших уже куплено — у всіх з'являється номер 3, потім 4; власників видно»):
  список власників і наступний номер — лише з сервера (`GET /api/owners` → `NX.owners.set`, `nextNo`); оновлювати при відкритті
  лабораторії й аркуша купівлі та раз на хвилину, поки вони відкриті. Номер дає сервер у мить успішної оплати (транзакція:
  `max(no) + 1`), тож двоє, що бачили #003 одночасно, отримають #003 і #004 — без пропусків і повторів.
- **Образ — в акаунті:** `GET/PUT /api/me` зберігає й віддає `look` (той самий ключ образу), щоб у кожного користувача його Nexi
  був однаковим на всіх пристроях; localStorage — лише запасний (без входу). Увага: при запуску `main.js` скидає збережений
  образ, якого не можна залишити, — з бекендом спершу дочекатися списку власників (`NX.owners.load()`), інакше свій куплений
  Nexi при перезапуску на мить вважатиметься чужою приміркою й зітреться.

### Оплата (крок 3)
- **Stripe Checkout** (EUR 99,99): картка, **iDEAL** (у Нідерландах — основний спосіб), Apple / Google Pay; Stripe Tax — ПДВ.
  **Увага:** у Stripe «first-party NFT minting and sales» — **обмежена** категорія (потрібне окреме схвалення Stripe, може
  бути відкликане), а продажі NFT на вторинному ринку через Stripe — заборонені. Тобто: подати заявку й чесно описати продукт
  (персональний скін для AI-помічника + NFT 1/1 від нас самих); поки чекаємо — тестовий режим.
- Запасний варіант — сервіс, зроблений саме для NFT за картку (напр. Crossmint: оплата карткою, NFT на гаманець за email;
  частина можливостей — корпоративний план). Вирішити після відповіді Stripe.
- ПДВ: цифрові послуги споживачам ЄС — ПДВ країни покупця (схема OSS). Право на відмову 14 днів для цифрового вмісту —
  лише якщо покупець явно погодився на негайне виконання (галочка перед оплатою) — перевірити з юристом.

### NFT на Base (крок 4)
- Контракт **ERC-721 «Nexora Nexi» (NEXI)**, OpenZeppelin v5: `ERC721` + `ERC2981` (роялті) + `AccessControl`
  (`MINTER_ROLE` — лише серверний гаманець), власник колекції — окремий захищений гаманець (краще апаратний / мультипідпис).
- `mint(to, id, key)`: лише MINTER; `require(!keyTaken[keccak256(key)])`; `id` = номер Nexi (#001 → 1).
- «Один Nexi на гаманець» — у `_update`: якщо `to != 0` і `from != to` — `require(balanceOf(to) == 0)` (діє й на перепродажі).
- Метадані (JSON): `name` «Nexi #001», `description`, `image` — PNG картки (той самий `nft_card.js` + `sprite.js`, намальовані
  на сервері: `tools/nft/render.js`, `@napi-rs/canvas`; OpenSea радить ≥ 3000 px — піксель-арт 96×128 ×32 = 3072×4096 без
  розмиття), **`animation_url` — ЖИВА картка** (власник, 03.11: «картка теж має бути анімованою, живою»): HTML-сторінка з тим
  самим кодом (`NX.nftCard.play`; OpenSea показує HTML зі скриптами на сторінці NFT) або відео MP4/WebM циклу 4 с; у списках і
  гаманцях, що не грають анімацію, — `image`. Кадр — `NX.nftCard(look, {no}, cv, t)`: поза й кліпання Nexi та все на картці
  кратні циклу (LOOP 4 с); крила, плащ і реліквії мають свої ритми — для відео чи GIF без шва на кроці 4 підігнати їх під 4 с
  (або цикл 8–12 с). Обмеження OpenSea — до 300 МБ (радять < 200).
  `attributes` — 8 частин (англійською: Color, Body, Arms, Legs, Antenna, Head, Back, Relic) і Code. Зберігання — IPFS
  (Pinata) або Arweave: після мінту не змінюється. `contractURI` — опис колекції для OpenSea.
- Спершу **Base Sepolia** (тестова мережа) → перевірки → **Base**.

## Що потрібно від власника (перед кроками 2–4)
- **Бізнес:** зареєстрований (у Нідерландах — KVK, номер BTW) — для платіжного сервісу, ПДВ і умов продажу.
- **Акаунти:** Stripe (заявка на продаж NFT) або Crossmint; Coinbase Developer Platform (гаманці за email + серверний гаманець);
  база (Neon / Supabase); Pinata (IPFS); **хостинг для комерції** — Vercel Pro ($20/міс; Hobby — лише некомерційне) або
  Cloudflare Pages.
- **Гаманець колекції** (власник контракту й одержувач роялті) і трохи ETH на Base для газу мінтів.
- **Документи:** умови продажу, політика приватності (email, гаманці), опис NFT (що отримує покупець) — з юристом.
- **MiCA:** унікальні NFT 1/1 зазвичай поза MiCA (ст. 2(3) — «унікальні й незамінні»), але регулятори оцінюють по суті:
  великі серії — ознака взаємозамінності. Наші Nexi — кожен свій, по одному; підтвердити з юристом.
- Секрети (ключі API, webhook, мінтера) — **лише в змінних середовища** хостингу, ніколи в репозиторії.
